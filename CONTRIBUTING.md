# Як долучитися

## 🔄 Як ми працюємо над текстом (Word-центричний workflow)

**Microsoft Word — основний інструмент редагування.** Схема така:

```
zvernennya.docx (Word, OneDrive)  ←→  zvernennya.md (git, офіційна версія)
        ↑ редагують усі                       ↑ фіксується через PR
```

1. **Редагування — у Word.** Файл `zvernennya.docx` лежить у OneDrive-папці
   репозиторію. Власник ділиться лінком «може редагувати» (**Поділитися →
   Будь-хто з посиланням може редагувати**) — і всі правлять одночасно:
   у десктопному Word, безкоштовному Word Online або LibreOffice. Працюють
   співавторство в реальному часі, автозбереження та журнал версій
   (**Файл → Відомості → Журнал версій**).
2. **Пропозиції — через Track Changes.** Увімкніть **Рецензування →
   Відстежувати зміни**, щоб було видно, хто що запропонував. Обговорення —
   через коментарі Word прямо в документі.
3. **Фіксація в git.** Коли порція правок узгоджена, мейнтейнер запускає:

   ```powershell
   ./import-docx.ps1   # Word → markdown (Track Changes приймаються)
   git diff zvernennya.md   # переглянути, що змінилось
   git add zvernennya.md; git commit
   ```

4. **Зворотний напрямок.** Якщо текст правили у markdown (через PR на GitHub):

   ```powershell
   ./export-docx.ps1   # markdown → Word
   ```

   Також GitHub Action автоматично збирає `zvernennya.docx` при кожній зміні
   `zvernennya.md` у `main` (**Actions → Artifacts → zvernennya-docx**).
5. **Оформлення — теж у Word.** Стилі фінального документа (шрифти, відступи,
   кольори) живуть у `template.docx` — відкрийте його у Word, змініть стилі
   (саме стилі, не текст) і закомітьте. Експорт автоматично їх підхопить.

> ⚠️ `zvernennya.docx` git ігнорує — це робоча чернетка, яку синхронізує
> OneDrive. Джерело правди для офіційної версії — `zvernennya.md`.
> Потрібен [pandoc](https://pandoc.org): `winget install --id JohnMacFarlane.Pandoc -e`.

## Підписати звернення

1. Зробіть fork цього репозиторію (або створіть гілку, якщо маєте доступ).
2. Додайте рядок зі своїм підписом у таблицю в [SIGNATURES.md](./SIGNATURES.md):
   - імʼя або нік;
   - контакт — за бажанням (Telegram, e-mail);
   - дата у форматі `YYYY-MM-DD`.
3. Відкрийте Pull Request з назвою `signature: <ваш нік>`.

## Запропонувати правки до тексту звернення

- Запропонуйте правку прямо у Word-документі `zvernennya.docx` (Track Changes), або
- відкрийте Issue з описом пропозиції, або
- одразу Pull Request зі змінами в [zvernennya.md](./zvernennya.md).

Текст звернення фіналізується після обговорення у спільноті — до того моменту
правки вітаються.

## Додати матеріали

Скриншоти проблем (таймаути, розсинхронізація статусів) додавайте в папку
`assets/` з описовою назвою файлу, наприклад `2026-11-07-timeout-status-page.png`.
