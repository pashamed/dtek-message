# Як долучитися

## 🔄 Як ми працюємо над текстом (workflow)

Ми використовуємо **гібридний підхід**:

1. **Чернетка та обговорення** — у спільному Word-документі `zvernennya.docx`,
   що лежить у OneDrive. Власник ділиться лінком «може редагувати» (у Word:
   **Поділитися → Будь-хто з посиланням може редагувати**), і всі правлять
   одночасно — у десктопному Word, Word Online або LibreOffice. Git цей файл
   ігнорує — він лише для чернетки. Лінк на документ — у чаті спільноти.
2. **Фіксація фіналу** — узгоджений текст переноситься в [README.md](./README.md)
   через Pull Request. Репозиторій — єдине джерело правди для офіційної версії.
3. **Експорт у Word** — для офіційної відправки `.docx` генерується автоматично:
   - **GitHub Action**: при кожній зміні `README.md` у гілці `main` збирається
     `zvernennya.docx` — завантажте його зі вкладки **Actions → останній запуск →
     Artifacts → zvernennya-docx**;
   - **локально**: запустіть `./export-docx.ps1` (потрібен
     [pandoc](https://pandoc.org): `winget install --id JohnMacFarlane.Pandoc -e`).

> ⚠️ Не комітьте `.docx`/`.odt` файли в репозиторій — git не вміє зливати бінарні
> формати, і паралельні правки загубляться. Правимо лише Markdown.

## Підписати звернення

1. Зробіть fork цього репозиторію (або створіть гілку, якщо маєте доступ).
2. Додайте рядок зі своїм підписом у таблицю в [SIGNATURES.md](./SIGNATURES.md):
   - імʼя або нік;
   - контакт — за бажанням (Telegram, e-mail);
   - дата у форматі `YYYY-MM-DD`.
3. Відкрийте Pull Request з назвою `signature: <ваш нік>`.

## Запропонувати правки до тексту звернення

- Відкрийте Issue з описом пропозиції, або
- одразу Pull Request зі змінами в [README.md](./README.md).

Текст звернення фіналізується після обговорення у спільноті — до того моменту
правки вітаються.

## Додати матеріали

Скриншоти проблем (таймаути, розсинхронізація статусів) додавайте в папку
`assets/` з описовою назвою файлу, наприклад `2026-11-07-timeout-status-page.png`.
